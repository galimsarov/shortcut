# Задачи по Java Advanced Core

Ниже — по 2 задачи на каждую тему:
- **Простой уровень** — базовая практика ключевых концепций.
- **Средний уровень** — комбинирование нескольких идей и чуть больше проектирования.

Ориентируйтесь на примеры из `docs/b_java-advanced-core-guide.md` и пакет `com.example.c_advanced_core`.

---

## 1) Коллекции

### 1.1 Простой: Каталог книг по жанрам
**Задача:**
Реализовать консольную программу, которая хранит книги по жанрам.

**Требования:**
1. Использовать `Map<String, List<String>>` (ключ — жанр, значение — список книг).
2. Добавить методы:
    - `addBook(String genre, String title)`
    - `printBooksByGenre(String genre)`
    - `printAllGenres()`
3. Если жанр отсутствует — создать его автоматически.
4. Не допускать дубликатов книг внутри одного жанра.

**Подсказка:** можно перейти на `Map<String, Set<String>>`, если хотите проще решать задачу с дубликатами.

### 1.2 Средний: LRU-кэш последних запросов
**Задача:**
Сделать кэш фиксированного размера для строковых запросов (например, URL).

**Требования:**
1. Использовать `LinkedHashMap` с режимом access-order.
2. Ограничить размер кэша (например, 5 элементов).
3. При переполнении удалять самый старый по использованию элемент.
4. Реализовать методы:
    - `put(String key, String value)`
    - `get(String key)`
    - `printState()`
5. Показать в `main`, как меняется порядок элементов после `get`.

## 2) Iterable / Iterator

### 2.1 Простой: Диапазон чисел с шагом
**Задача:**
Сделать свой класс `IntRange`, который можно использовать в `for-each`.

**Требования:**
1. Класс реализует `Iterable<Integer>`.
2. Поддерживает параметры: `start`, `end`, `step`.
3. Итерация идёт от `start` до `end` (включительно или исключительно — зафиксировать и документировать).
4. Добавить проверку на некорректный `step` (например, `0`).

### 2.2 Средний: Итератор по истории браузера
**Задача:**
Реализовать структуру `BrowserHistory`, которая хранит посещённые страницы и даёт итератор.

**Требования:**
1. Хранение на базе `List<String>`.
2. Кастомный `Iterator<String>`:
    - поддерживает `next`, `hasNext`, `remove`.
3. `remove` должен удалять текущий элемент корректно и без `ConcurrentModificationException`.
4. Добавить 2 режима обхода:
    - от старых к новым,
    - от новых к старым.

## 3) Comparable / Comparator

### 3.1 Простой: Сортировка студентов по `Comparable`
**Задача:**
Создать класс `Student` и реализовать естественный порядок сортировки.

**Требования:**
1. Поля: `id`, `name`, `gpa`.
2. Реализовать `Comparable<Student>`:
    - сначала по `gpa` (по убыванию),
    - при равенстве — по `name` (по возрастанию).
3. Продемонстрировать сортировку списка через `Collections.sort`.

### 3.2 Средний: Набор компараторов для товаров
**Задача:**
Для класса `Product` реализовать несколько стратегий сортировки.

**Требования:**
1. Поля: `name`, `price`, `rating`, `category`.
2. Создать компараторы:
    - по цене,
    - по рейтингу,
    - по категории + цене,
    - по имени без учёта регистра.
3. Добавить составной компаратор с `thenComparing`.
4. Сделать утилитный метод `sortProducts(List<Product>, Comparator<Product>)`.

## 4) Исключения

### 4.1 Простой: Проверка возраста пользователя
**Задача:**
Сделать метод регистрации, который валидирует возраст.

**Требования:**
1. Метод `register(int age)`:
    - если возраст < 18, бросать собственное checked-исключение `UnderAgeException`.
2. В `main` показать обработку через `try-catch` и понятное сообщение пользователю.
3. Добавить ветку успешной регистрации.

### 4.2 Средний: Мини-обработчик платежей с иерархией исключений
**Задача:**
Смоделировать процесс оплаты с несколькими типами ошибок.

**Требования:**
1. Базовое исключение `PaymentException`.
2. Наследники:
    - `InsufficientFundsException`,
    - `CardExpiredException`,
    - `PaymentGatewayException`.
3. Метод `pay(...)` может бросать разные исключения в зависимости от условий.
4. В вызывающем коде:
    - отдельно обработать бизнес-ошибки,
    - отдельно — технические,
    - добавить `finally` для логирования завершения операции.

## 5) Дженерики

### 5.1 Простой: Универсальная коробка
**Задача:**
Реализовать generic-класс `Box<T>`.

**Требования:**
1. Методы `set(T value)` и `get()`.
2. Продемонстрировать использование с разными типами (`String`, `Integer`, кастомный класс).
3. Показать, чем generic-версия безопаснее сырого типа.

### 5.2 Средний: Утилиты с wildcard (PECS)
**Задача:**
Сделать generic-утилиты для копирования и агрегации чисел.

**Требования:**
1. Метод `copy(List<? extends T> src, List<? super T> dst)`.
2. Метод `sumNumbers(List<? extends Number> numbers)`.
3. Продемонстрировать работу с `List<Integer>`, `List<Double>`, `List<Number>`.
4. Коротко объяснить в комментариях, где producer, а где consumer.

## 6) Stream API

### 6.1 Простой: Аналитика по списку строк
**Задача:**
Для списка слов получить агрегированную статистику через Stream API.

**Требования:**
1. Отфильтровать слова длиной меньше 4.
2. Привести к нижнему регистру.
3. Удалить дубликаты.
4. Отсортировать по алфавиту.
5. Собрать в `List<String>` и вывести результат.

### 6.2 Средний: Отчёт по заказам
**Задача:**
Сформировать отчёт по коллекции заказов `Order`.

**Требования:**
1. Поля заказа: `id`, `customer`, `amount`, `status`, `createdAt`.
2. Через stream получить:
    - сумму завершённых заказов,
    - топ-3 клиентов по сумме,
    - группировку по статусам,
    - средний чек.
3. Использовать `groupingBy`, `mapping`, `reducing` или `summarizingDouble`.
4. Сравнить один из шагов с императивной реализацией (2–3 строки комментария).

## 7) I/O

### 7.1 Простой: Копирование текстового файла
**Задача:**
Скопировать содержимое одного текстового файла в другой.

**Требования:**
1. Вход: путь к исходному и целевому файлу.
2. Использовать `BufferedReader`/`BufferedWriter`.
3. Сохранять структуру строк (переносы).
4. Использовать `try-with-resources`.

### 7.2 Средний: Поиск самого длинного слова в файле
**Задача:**
Прочитать большой текстовый файл и найти самое длинное слово.

**Требования:**
1. Читать файл построчно (без загрузки целиком в память).
2. Учитывать пунктуацию (очищать слово от знаков).
3. Вывести:
    - слово,
    - длину,
    - номер строки, где оно впервые встретилось.
4. Добавить обработку ошибок ввода-вывода.

## 8) Сериализация

### 8.1 Простой: Сохранение и восстановление профиля
**Задача:**
Сериализовать объект `UserProfile` в файл и прочитать обратно.

**Требования:**
1. Класс реализует `Serializable`.
2. Поля: `username`, `email`, `age`.
3. После десериализации сравнить поля исходного и восстановленного объекта.
4. Добавить `serialVersionUID`.

### 8.2 Средний: transient и кастомная сериализация
**Задача:**
Сделать класс `Account`, где часть данных не должна сохраняться напрямую.

**Требования:**
1. Поля: `login`, `passwordHash`, `sessionToken`.
2. `sessionToken` сделать `transient`.
3. Реализовать `writeObject/readObject` для дополнительной валидации (например, проверка формата `login`).
4. Показать, какие поля сохранились/восстановились после десериализации.

## 9) Копирование объектов

### 9.1 Простой: Shallow vs Deep copy для пользователя
**Задача:**
Смоделировать пользователя с вложенным объектом адреса и показать разницу shallow/deep copy.

**Требования:**
1. Классы `User` и `Address`.
2. Реализовать:
    - поверхностную копию,
    - глубокую копию (через конструктор копирования).
3. После изменения адреса в копии показать поведение оригинала в обоих случаях.

### 9.2 Средний: Мини-реестр прототипов игровых юнитов
**Задача:**
Сделать реестр шаблонов объектов и их клонирование (паттерн Prototype).

**Требования:**
1. Базовый абстрактный класс `GameUnit` с методом `copy()`.
2. Минимум 2 типа юнитов (например, `Warrior`, `Mage`) с вложенными mutable-полями.
3. `UnitRegistry` хранит прототипы по ключу и возвращает копии.
4. Продемонстрировать, что изменение клонов не меняет прототипы.
